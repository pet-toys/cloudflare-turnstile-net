10.2.0
======

Added:
- Turnstile options are now validated when the host starts. A missing or empty
  secret key fails the application with a message naming the property, instead
  of leaving every verification to fail silently against Cloudflare at request
  time.
- The verification HttpClient is now registered with a 10-second timeout in
  place of the framework default of 100 seconds, so an unresponsive endpoint no
  longer holds a request thread. The overload that exposes the HttpClient
  builder still overrides it, resilience handlers included.

Changed:
- MVC actions now skip verification for GET, HEAD, and OPTIONS requests, as
  Razor Pages handlers already did. Applying the validation attribute to a whole
  controller no longer demands a Turnstile token from every read it serves.
- The site key is no longer required. It belongs to the browser widget and the
  server-side verification path never reads it, so applications that render the
  widget elsewhere, or render none at all, no longer have to configure a value.
  The secret key stays required.

Fixed:
- A siteverify response that cannot be read as Cloudflare's documented JSON --
  an empty or malformed body, or an error page served by a proxy under a 200 --
  now resolves to a failed verification instead of surfacing as an unhandled
  server error on the protected form post. Caller-initiated cancellation still
  propagates.

----------

10.1.3
======

Changed:
- Packages are now published to NuGet.org through trusted publishing, so the
  release pipeline no longer depends on a long-lived API key.

----------

10.1.2
======

Fixed:
- Internal await points no longer capture the caller's synchronization context,
  avoiding potential deadlocks in synchronous-over-asynchronous call paths and
  removing needless context marshalling in the consuming application.

----------

10.1.1
======

Fixed:
- Transport-level failures when contacting Cloudflare (DNS errors, refused
  connections, timeouts, or an outage) now resolve to a failed verification
  instead of surfacing as an unhandled server error. Caller-initiated
  cancellation still propagates.
- The idempotency key is now derived deterministically from the verified token,
  so resubmitting the same token is checked idempotently instead of being
  rejected as already spent.
- The MVC and Razor Pages validation filter no longer reuses a request-scoped
  service across requests, so every request is verified with current options
  and its own idempotency key.

----------

10.1.0
======

Added:
- VerifyAsync now accepts an optional CancellationToken and passes it through
  the verification HTTP call, so callers can cancel an in-flight check.

Changed:
- Empty, missing, or whitespace-only tokens now resolve to a failed result
  immediately, without calling Cloudflare.

Fixed:
- The field-level error message is now attached to the form field's model-state
  key, so it surfaces through asp-validation-for instead of only the validation
  summary.
